## 0.当前的问题
知拾的架构是否适合我们的目标？要是想要让知拾变成我们的目标，该做什么，下面是一份工程化的设计文档，由王晨编写
### 当前程序功能分析
目前的程序实现了这样的功能：
1. 用户可以在程序里面拥有自己的知识库
2. Agent可以自动检索知识库的内容，并提供回答给用户
3. llm每次进入程序都会提供意见给用户
4. 用户可以通过拍照，自己上传文档和使用无障碍功能来把一些资料或者手机里面随手看到的感兴趣的内容变为自己的知识库内容
5. 参考4.实现的功能，知识库的功能变成了一个接入了Agent的内容存储库，也就是第二大脑
6. agent会根据用户知识库里面的时效性内容进行日程提醒和计划追踪。

这样来看，之前软件实现的很杂，但是还是为我们的项目提供了良好的架构基础，
但是目前的UI/UX部分问题很多，之前软件的目标是朝向怎么变成用户的第二大脑构建的，现在我们的目的是，怎么让用户通过我们的软件来提升自己，这个是一个颇有挑战性的目标。
## 1. 用户如何得到提升？程序自动化题目生成和让用户自动询问
我的设计如下：
1. 用户添加进入知识库的文档（参考[第二节](#2-程序怎么样自动化生成题目使用知识库内容区分)）,使用Agent技术构建属于用户的问题集，用户可以点击对于资料进行刷题
2. 程序里面的Agent可以自动参考每一章节的编者编写的题目，并扩展一些llm自动生成的题目
3. 在实现上，用户的数据表结构按照（用户id,用户知识库分类id，对应题目，对应题目id，题目TAG，绑定的文档对应章节内容）对应题目id按照用户id，用户知识库id，随机uuid自动生成随机的题库（题目tag参考[第二节](#2-程序怎么样自动化生成题目使用知识库内容区分)）
4. 在广泛的用户基础上，自动化生成的题目可以进入更大的题库，通过哈希去重和唯一id可以免去重复生成和多用户贡献以及用户答题参考
5. 用户答题界面更加人性化，不再是答对或者打错下一个，而是主动添加一个答案就是我不会，想和Agent聊聊，Agent可以获取绑定的文档对应章节内容来为他解释并不断引导他发掘答案
6. 当用户答错的时候，可以自动的在下面放出原文内容和答案解析
## 2. 程序怎么样自动化生成题目？使用知识库内容区分
在之前我们的软件遵循着无论是什么东西，都可以被添加进入知识库，然后让llm帮忙分类，但是为了这个目标，我们需要这样修改：
1. 按照内容区，添加多种区分，例如 学习区 这个一个分类来放置用户想要学习的资料，生活区里面可以放置一些用户自己的笔记等
2. 学习区的资料除了进入知识库可以被Agent检索之外，同时会自动的建立索引和提取该资料的tag （这个是一个难点，这个tag是让Agent提取的话，是要Agent得看完全资料或者资料带有tag的，建议想另一种方案，互联网获取或者用户添加），
3. 在2.之上，Agent可以提取里面的题目和自己扩展题目来编写题库（难点，如何查找题目和题目进入库中）
4. 题库变为全局的，用户上传了一个文件之后和系统的全局文档检索表发现哈希一致，就只是存储一份，然后用户这边就是多出来一个引用就好，Agent生成的题目放在在系统的全局数据库里面 
## 3. 更有用的聊天界面：让Agent伴随知识库回答
目前的聊天界面和普通的AI产品没有任何区别
1. 进入对话界面的时候，用户可以选择一个知识库进行对话的开始，而不是直接全局的对话
2. 前端设计，这里临时插入，Agent回答的时候，要求在回复的文本里面添加对文件的具体位置的引用，同时前端可以直接打开并高亮显示
