# 6.文件树与目录结构

> 本文是知序 Web 的源码与测试文件树真相源。本文展示 `src/` 真实运行源码和 `tests/` 测试源码；根目录配置、`docs/`、`public/`、生成产物、本地工具目录和依赖目录不在本文展开。架构边界以 `docs/2.技术架构文档.md` 为准；API 字段以 `docs/4.API接口文档.md` 为准。

## 1. 统计口径

统计范围：当前工作区 `src/` 与 `tests/` 目录下的所有目录和文件。

不展示范围：

- 根目录配置文件，例如 `package.json`、`vite.config.ts`、`tsconfig*.json`、`tailwind.config.js`。
- 文档目录，例如 `docs/`。
- 静态资源目录，例如 `public/`。
- 依赖、构建、渲染、本地工具和历史目录，例如 `node_modules/`、`dist/`、`.agents/`、`.claude/`、`.codegraph/`、`video/`、`renders/`。

| 范围 | 目录 | 文件 |
| --- | ---: | ---: |
| `src/` | 38 | 172 |
| `tests/` | 22 | 28 |
| 合计 | 60 | 200 |

## 3. 目录归属规则

| 目录 | 职责 | 新文件归属 |
| --- | --- | --- |
| `src/components/auth` | 登录恢复、受保护路由等鉴权边界组件 | 只放跨页面复用的鉴权外壳组件 |
| `src/components/blocks` | 带知序业务语义、可跨页面复用的展示块 | 放卡片、列表、消息、统计、时间线等业务展示块 |
| `src/components/layout` | 全局工作台布局骨架 | 放 `AppShell`、侧栏、顶栏、右栏和布局级加载组件 |
| `src/components/ui` | 低业务语义基础 UI 控件 | 放按钮、输入框、弹窗、菜单、表格等 shadcn/Radix 风格组件 |
| `src/context` | 跨页面 UI 或主题上下文 | 只放 UI/主题类上下文；鉴权状态归 `src/lib/auth` |
| `src/data` | mock/demo/默认展示数据 | 放样例数据和默认空状态数据，不作为真实业务数据源 |
| `src/features` | 页面级业务功能域 | 新页面优先放对应功能域目录，复杂子组件放同 feature 内 |
| `src/hooks` | 跨功能复用的通用 hook | 放不绑定单一页面业务的异步、确认、健康检查、通知等 hook |
| `src/lib/api` | API 客户端、端点封装和 DTO | 新 API 先更新 `docs/4.API接口文档.md`，再在此处实现；测试放 `tests/unit/lib/api` |
| `src/lib/auth` | 鉴权状态、Token、登录会话和开发鉴权辅助 | 放鉴权上下文、hook 和开发鉴权相关文件；测试放 `tests/unit/lib/auth` 或 `tests/integration/auth` |
| `src/lib/demo` | 开发模式本地示例数据层 | 放未接入真实后端前的本地闭环 store、hooks；测试放 `tests/unit/lib/demo` |
| `src/lib/theme` | 主题方案和主题类型 | 放主题配置、主题类型和主题工具 |
| `src/routes` | React Router 路由表 | 新页面注册路由时同步更新此处 |
| `src/types` | 前端业务类型 | 放跨页面复用的前端业务模型 |
| `tests/setup` | Vitest 测试环境配置 | 放全局 matcher、测试环境初始化和 polyfill |
| `tests/unit` | 单元测试 | 放纯函数、DTO 适配、状态转换、API 契约等不渲染完整页面的测试 |
| `tests/components` | 跨页面组件测试 | 放布局组件、通用组件等组件级渲染测试 |
| `tests/features` | 页面级功能测试 | 放功能页面的用户流程、筛选、交互和接口状态测试 |
| `tests/integration` | 跨模块集成测试 | 放 Provider、路由门禁、浏览器存储、API mock 协作等测试 |

## 4. 维护规则

- 本文只展示 `src/` 和 `tests/` 下的文件树，不再展开其他目录。
- 创建、删除、移动或重命名 `src/` 或 `tests/` 下任何文件后，必须同步更新本文的文件树和统计数量。
- `src/` 只放真实运行源码；测试文件、测试 setup、测试 fixture 默认归入 `tests/`。
- 修改非 `src/`、非 `tests/` 文件时，本文无需新增对应路径；如本次修改只影响本文自身，也只需保持本文“只展示 `src/` 和 `tests/`”的口径。
- 新增页面时同步核对 `src/routes/index.tsx`、`src/data/nav.ts`、`src/components/layout/Topbar.tsx`。
- 新增 API 时先更新 `docs/4.API接口文档.md`，再更新 `src/lib/api`。
- 新增测试时按 `tests/setup`、`tests/unit`、`tests/components`、`tests/features`、`tests/integration` 归类，不在 `src` 目录旁边创建 `.test.*` 文件。
- 不把 `node_modules/`、`.git/`、`dist/`、本地工具目录、渲染产物或历史目录写入本文文件树。
