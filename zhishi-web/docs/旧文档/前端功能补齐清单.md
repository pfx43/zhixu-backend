# 知序 Web 前端最小需求清单

> 审核日期：2026-07-04
>
> 依据：`docs/1.产品需求文档.md` 与用户提供的四张产品思维导图截图。
>
> 文档定位：把产品最小闭环拆成 Web 前端需要完成的界面、交互和状态。后端需求见 `docs/后端能力补齐清单.md`。

## 1. 总体结论

当前 Web 前端最小目标不是先补齐所有工作台页面，而是先完成个人端产品闭环：

```text
上传资料 -> 形成个人知识库 -> 基础 AI 问答 -> 对话确认画像
-> 生成带可信度的个人知识图谱 -> 用户修正画像
-> 普通模式苏格拉底式引导 -> 付费模式入口
```

因此前端需求优先级应从“页面按钮是否都能点”调整为“能否让用户建立画像并看到画像变准”。

## 2. 当前最小范围

| 范围 | 是否进入当前最小闭环 | 前端要求 |
| --- | --- | --- |
| 基础功能 + 普通模式 | 是 | 免费可用，完成上传、知识库、基础问答、画像构建、基础先修提示 |
| 知识追踪模式 | 分阶段进入 | 先展示入口和权益，逐步接入图谱、掌握度、可信度、路径、LVR |
| 推理模式 | 分阶段进入 | 先展示入口和权益，逐步接入风险识别、推理链验证和解释 |
| 机构端/学校端/家长端 | 不进入当前最小闭环 | 不在个人 Web 中误承诺完整机构能力 |

## 3. P0：基础功能 + 普通模式

### 3.1 模式入口和商业层级

前端需实现：

1. 在首页、聊天页或设置页明确展示三层模式：
   - 基础功能 + 普通模式：免费。
   - 知识追踪模式：付费层一。
   - 推理模式：付费层二。
2. 普通模式可直接使用。
3. 知识追踪模式和推理模式在未开通时展示权益说明和升级入口。
4. 不把未开通模式伪装成已生效能力。

验收标准：

- 用户能理解当前处于哪个模式。
- 用户能理解升级后获得什么能力。
- 前端不会在免费模式中展示“已完成 LEKT / Dynamic-e / CABR”的误导性状态。

### 3.2 上传资料

产品目标：

- 引导用户投入其认为需要用于构建个人画像的资料。
- 多模态处理资料，并提取核心内容写入个人知识库。

前端需实现：

1. 上传入口支持图片、PDF、音频、文本四类资料的选择提示。
2. 上传前提示这些资料会用于构建个人知识库和个人画像。
3. 上传任务展示状态：等待、上传中、解析中、写入知识库、失败、完成。
4. 上传完成后引导用户进入画像确认或知识库查看。
5. 失败时展示可理解原因和重试入口。

当前相关页面：

- `src/features/knowledge-base/UploadPage.tsx`
- `src/features/knowledge-base/KnowledgeBasePage.tsx`

### 3.3 个人知识库

产品目标：

- 本地优先存储。
- 形成个人知识库。
- 支持检索。

前端需实现：

1. 知识库列表展示用户上传资料。
2. 文档详情或预览展示提取出的核心文本。
3. 知识库搜索能检索资料名称和内容摘要。
4. 空状态引导用户上传第一份资料。
5. 页面文案明确“个人知识库是画像基础”。

本地优先与迁移文案：

- 前端需要在设置或知识库页面说明：默认本地优先。
- 换设备时可选择一次性云端迁移。
- 下载回本地后，云端数据应消失。

### 3.4 基础 AI 问答

产品目标：

- 基础 Q&A 是冷启动入口。
- 免费层无画像加持或仅使用基础画像。

前端需实现：

1. 聊天页保留基础提问入口。
2. 当用户尚未完成画像构建时，明确提示当前是冷启动问答。
3. 回答过程应尽量使用苏格拉底式引导：先提问、再引导，不直接给结论。
4. 用户从顶栏搜索或首页 AI 搜索进入聊天时，保留问题上下文。

当前相关页面：

- `src/features/chat/ChatPage.tsx`
- `src/components/layout/Topbar.tsx`
- `src/features/dashboard/DashboardPage.tsx`

### 3.5 个人画像构建入口

产品目标：

- 从用户资料和确认对话中形成个人画像。
- 画像不得基于猜测。

前端需实现：

1. 增加“构建个人画像”的明确入口。
2. 首次进入时引导用户：
   - 先上传资料。
   - 选择哪些资料用于画像。
   - 开始画像确认对话。
3. 展示画像构建进度：
   - 资料已导入。
   - 对话确认中。
   - 画像已生成。
   - 等待用户修正。
4. 当资料不足时，以提问方式引导用户补充，而不是给出结论。

建议落点：

- 可先在 `ProfilePage` 增加画像构建模块。
- 也可以在 `DashboardPage` 增加画像构建任务卡。

### 3.6 对话确认画像

产品目标：

- AI 基于用户提供资料进行轮询对话，以确认自己对用户的了解。
- 不进行猜测。

前端需实现：

1. 画像确认对话与普通聊天区分。
2. 每轮确认问题展示来源依据，例如来自哪份资料或哪段用户回答。
3. 用户可回答“正确 / 不准确 / 需要补充”。
4. 对“不准确”的内容进入修正流程。
5. 完成后生成或更新画像节点。

验收标准：

- 用户能看出系统是在确认，而不是直接给画像结论。
- 用户能修正系统对自己的理解。

### 3.7 可信度知识图谱

产品目标：

- 个人画像存在于知识图谱中。
- 每个节点都有可信度。
- 可信度通过百分比和圆圈颜色可视化。

前端需实现：

1. 画像图谱页面展示节点、关系和可信度。
2. 节点显示可信度百分比。
3. 节点颜色表达可信度区间。
4. 点击节点展示：
   - 节点含义。
   - 可信度。
   - 依据资料。
   - 最近确认时间。
5. 用户可标记“与我实际不符”。
6. 标记后进入对话确认和修正流程。

当前相关页面：

- `src/features/knowledge-graph/KnowledgeGraphPage.tsx`
- `src/features/profile/ProfilePage.tsx`

### 3.8 普通模式先修提示

产品目标：

- 普通模式做基础先修校验。
- 有先修图就用，没有先修图时不硬拦截，只提示。

前端需实现：

1. 用户提出学习问题时，展示“可能需要先了解”的基础提示。
2. 提示不阻断用户继续提问。
3. 没有先修数据时，展示“当前仅做相关性提示”。
4. 提示内容可以进入聊天追问。

验收标准：

- 普通模式不会把用户挡在学习入口外。
- 前端不展示强制拦截式错误。

## 4. P1：知识追踪模式

知识追踪模式是付费层一，目标是从“哪里不会”升级为“为什么不会”。

前端需实现：

1. 知识追踪模式开通状态。
2. 完整知识图谱可视化。
3. 当前学科节点掌握状态。
4. 当前学科节点可信度。
5. 先修断层定位结果。
6. 个性化学习路径。
7. 错题归因拆解。
8. `LVR` 实时监控。
9. 学习历史曲线。
10. 存储扩容提示。

体验要求：

- 出错时不只给答案，要展示真正缺失的先修节点。
- 学习路径要解释“下一步为什么补这里”。
- `LVR` 要让用户感知当前学习质量。

## 5. P2：推理模式

推理模式是付费层二，目标是主动防控高置信逻辑风险。

前端需实现：

1. 推理模式开通状态。
2. 高置信风险提示。
3. 多步推理链展示。
4. 每一步逻辑合理性检查结果。
5. 认知脆弱点主动暴露。
6. 跨域问题降级为相关性引导的提示。
7. 推理过程解释。

体验要求：

- 对“AI 很自信但可能逻辑错”的回答给出更严格审查提示。
- 对复杂推导题、跨章节综合题展示推理链。
- 对先修图不清楚的领域，不做硬拦截。

## 6. 当前不进入最小闭环的前端范围

以下能力可以保留页面或入口，但不作为当前最小闭环验收条件：

- 完整笔记 CRUD。
- 智能提醒 CRUD。
- 通知中心完整实现。
- 教师端。
- 机构管理端。
- 学校管理端。
- 家长报告。
- 公益版配额管理。

这些功能不删除，但实现顺序应排在个人画像闭环之后。

## 7. 建议前端实施顺序

1. 第一阶段：模式入口、上传资料、个人知识库、基础 Q&A。
2. 第二阶段：画像构建入口、确认对话、画像构建进度。
3. 第三阶段：可信度知识图谱、节点修正、画像动态更新。
4. 第四阶段：普通模式先修提示和苏格拉底式回答体验。
5. 第五阶段：知识追踪模式的图谱、掌握度、断层、路径、`LVR`。
6. 第六阶段：推理模式的风险提示、推理链验证和可解释过程。

| 个人知识库 | 已有知识库列表、预览、删除 | 需要内容检索、画像资料选择、本地优先说明 |
| 基础 AI 问答 | 已有聊天会话、历史会话和流式响应 | 需要冷启动状态、苏格拉底式引导、画像模式区分，以及从顶栏搜索带入问题 |
| Chat 模式按钮 | `高效笔记`、`AI 学习`、`默认知识库`、`推理模式`主要是本地 UI 状态 | 需要把模式写入请求，展示权限、上下文来源、输出目标和不可用原因 |
| Chat 关联知识库 | 显示“当前账号知识库”和工具按钮 | 需要可选择资料范围、展示引用命中、支持取消或切换知识库上下文 |

| 普通模式先修提示 | 学习页已有 KT 接口消费 | 缺少聊天中的非阻断先修提示 |
| 知识追踪模式 | 有学习分析、路径、图谱基础页面 | 缺少付费模式入口、真实状态持久化和 LVR 体验 |
| 推理模式 | Chat 有本地推理开关 | 缺少推理风险、推理链验证和可解释 UI |
| 笔记列表 | 使用 `sampleNotes`；筛选 chip 只改本地状态，排序/筛选按钮未打开面板 | 需要真实列表、搜索、排序、筛选、标签创建/编辑、分类整理和批量操作 |
| 笔记编辑 | 编辑器当前本地保存，注释已标明后续接 `updateNote` | 需要创建、更新、删除、自动保存、标签/分类编辑和 AI 生成笔记落库 |
| 学习路径 | 已消费 KT 图谱和学习路径接口，并有兜底推荐 | 需要把路径和画像/知识追踪模式绑定，展示“为什么下一步补这里”的证据链 |
| 智能提醒 | 页面和表单使用 `sampleReminders`，创建按钮不落库 | 需要提醒 CRUD、重复规则、关联资料、完成状态和通知联动 |

- “已实现”指页面真实调用 `src/lib/api`，并用接口结果驱动主要 UI。
