# 领域文档

本仓库采用单上下文领域文档布局。领域术语与难以逆转的架构决策按需记录，不提前创建空文档。

## 探索前读取

- 若根目录存在 `CONTEXT.md`，先读取其中的领域术语和边界。
- 检查 `docs/adr/` 中与当前任务相关的架构决策。
- 若文件不存在，静默继续；当术语歧义或架构决策真实出现时，再通过领域建模流程创建。

## 使用规则

- Issue、测试名称、接口和实现说明优先使用 `CONTEXT.md` 已定义的术语。
- 不为同一概念随意创造同义名称。
- 若计划与现有 ADR 冲突，必须在实施前明确指出，不能静默覆盖。

## 目标布局

```text
/
├── CONTEXT.md
└── docs/
    └── adr/
        └── NNNN-decision-name.md
```
