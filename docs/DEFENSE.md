# 答辩技术资料 — LEKT × 知拾 APP

## 项目一句话

> 传统 KT 模型预测准确但内部逻辑混乱，我们提出 LEKT 方法让 AI 真正"懂教育规律"，并集成到知拾 APP 验证实用性。

---

## 核心论点

### 问题发现

传统知识追踪的评价标准是 **AUC / Accuracy**，但高准确率≠真正理解学生。

| 典型问题 | 表现 |
|----------|------|
| 逻辑违反 | AI 认为学生会微积分但不会加法 |
| 优化偏差 | 只优化预测，不优化结构一致性 |

### 我们的方法：LEKT

在模型训练/推理中加入**教育先修约束**（软约束），不强行限制、不损失性能。

### 核心结果

- LVR（先修违反率）从 **27% → 接近 0%**
- 预测准确率**几乎不降**
- 首次提出"准确率+结构一致性"双维度评价

## 回答评委可能的问题

### Q1: 你的工作和其他 KT 方法有什么本质区别？

**A:** 其他方法只追求预测准确，我们发现了"高准确率伴随逻辑违反"这一反直觉现象，首次提出用先修约束保证认知状态的**结构一致性**。

关键不是"我们的模型更准"，而是"我们对学生的理解更合理"。

### Q2: 软约束和硬约束有什么区别？

**A:**
- **硬约束**：强制满足先修关系 → 训练不稳定、性能下降
- **软约束（我们的方法）**：在损失函数中加一个惩罚项，允许小幅度偏差 → 几乎不损失准确率

### Q3: LVR 从 27% 降到 0% 是怎么实现的？

**A:** 训练时加入 `logic_loss` 正则化项，惩罚违反先修约束的认知状态。推理时 LADL 算子做轻量修正。两者结合，消除几乎所有逻辑矛盾。

### Q4: 为什么用 Flutter APP 来验证？

**A:** 证明方法的实用性。LEKT 不仅是学术贡献，还能落地到真实教育场景——知识点依赖可视化、苏格拉底学习引导、个性化路径推荐。

### Q5: 你们的数据从哪来？

**A:** 先修矩阵（logic_matrix.npy）可由两种方式生成：
1. 自动管线：学生答题数据 → 统计筛选 → LLM 语义验证 → 先修矩阵
2. 专家标注：教师/教材直接标注知识点依赖关系

### Q6: 论文的创新点怎么总结？

**A:**
1. **发现新问题**：高预测准确率可能伴随严重结构逻辑错误（反直觉）
2. **提出新方法**：软约束 LEKT，几乎不损失性能同时消除逻辑矛盾
3. **建立新标准**：从单指标（AUC）转向双维度（准确率+一致性）评价
4. **工程落地**：集成到知拾 APP，苏格拉底教学 + 可视化分析
