## 产品设计
### A. 主 AI / General Tutor
这是用户和“知序这个人”长期沟通的地方。
用户可以在这里：
- 说自己想学什么；
- 探索兴趣；
- 讨论目标；
- 让 AI 帮他设计学习路径；
- 调整学习计划；
- 讨论最近学习状态；
- 说“你判断得不对”；
- 讨论学习习惯、偏好、情绪和节奏；
- 后续甚至切换到新的学习目标。
### B. Learning Workspace AI
当用户进入一本书、一个课程或者某个学习领域以后：
中间是：

**PDF / PPT / Word / 笔记 / 学习资料**

右边是：

**与当前资料强绑定的 AI。**

用户可以：

> “这一段什么意思？”

> “这个公式为什么这里能这么推？”

> “你结合我前面的状态看，我是不是缺了什么？”

甚至对着文中的某一句直接发问。（A与B多个学习入口，一个长期的“你”。）

### C.用户初次实验
用户第一次进入
      ↓
知序主动欢迎 + 简单告诉他怎么使用
      ↓
引导上传现在真实在使用的学习资料
      ↓
PDF / Word / PPT / 笔记 / 错题 / Excel……
      ↓
文件析解 + OCR + 切片 + 向量化 + 内容理解
      ↓
AI根据资料形成初步假设
“你现在是在学……？”
      ↓
3~5轮自然对话校准
      ↓
已知 / 待验证 / 未知
      ↓
必要时发起少量验证题/问题
      ↓
第一版 Learner State
      ↓
以后在真实学习中持续修改

### D.学习路径设计
知序不会要求用户第一次进入软件时就填写目标院校、考试日期、每天可学习时间、历史成绩等大量信息。
用户第一次进入知序，只需要正常使用。
例如：
> “我最近在学操作系统。”
或者：
> “我准备考研，但现在408学得很乱。”
甚至：
> “我只是想把线性代数学明白。”

知序首先通过对话和用户上传的资料了解他**现在正在做什么**，而不是强迫用户先定义一个完整目标。只有当用户进一步提出：
> “我想准备考研。”
> “帮我规划一下。”
> “我想三个月把这本书学完。”

这类真正需要学习计划的问题时，知序才会继续询问与计划有关的信息，例如：
当前基础、学习进度、目标、剩余时间、每天可以投入多少时间等。
随后知序生成一版学习方案。
用户可以：
**直接采用**  
→ 开始执行；
也可以：
**修改其中的时间、内容和优先级**  
→ 知序重新调整后续安排。

#个真实体验应该是
用户：

> “我准备考408，但我每天最多只能学三个小时。”

知序：

> “从你现在上传的资料看，操作系统已经进行到死锁部分，但前面的资源分配还有待确认。  
> 我建议暂时不要平均分配四科时间，先把这里验证清楚。要不要先给你做一版三小时/天的路线？”

用户：

> “可以，但我晚上不想学数学。”

知序：

> “好，我把数学调整到白天，同时重新计算后面的安排。”

所以：

计划不是知序替用户强制决定。

而是：
**知序提出方案 → 用户调整 → 系统继续理解用户 → 后续计划发生变化。**
始终保留“用户可以改变方案”这一层。当前商业研究同样指出，通用AI生成一个全年计划本身没有支付价值，真正的价值在于建议能够根据用户状态持续改变。

### E.资料上传核心
体验应该是：
> **我把自己的资料带进来以后，知序开始用这些东西认识我。**

例如用户上传：
- 一本王道操作系统PDF；
- 最近一周的错题截图；
- 自己写的笔记；
- 当前学习计划。
知序会分别理解这些内容。
教材告诉系统：

> **这个人在学什么。**

错题告诉系统：

> **这个人可能在哪里出现问题。**

笔记告诉系统：

> **这个人目前是怎么理解这些知识的。**

计划告诉系统：

> **这个人正在准备怎么学习。**

所以即使它们都是“文件”，对知序而言意义完全不同。

#用户看到的体验
上传结束后，不应该只出现：
> “文件上传成功，可以开始提问。”

而应该类似：

> **“我已经看完你刚才上传的资料。”**
> 
> “目前可以确认你正在学习操作系统，资料主要覆盖进程管理、死锁和内存管理。”
> 
> “从你的错题和笔记来看，我发现‘资源分配’这一块可能需要进一步确认。”
> 
> **“我暂时还不能确定你是真的不会，还是只是这几道题做错了。要不要让我问两个问题确认一下？”**

# 主体
## 产品定位与市场
产品定位：**面向自主学习者的 AI 学习操作系统**，首阶段从考研数学、408等高强度场景切入
核心痛点：**用户知道“哪里错”，却不知道**“真正哪里不会、为什么不会、下一步学什么”；用户能够获得答案、课程和错题分析，却仍难持续回答三个问题：  
**我真正哪里不会？为什么不会？下一步该学什么？**
**市场趋势与缺口：AI精准学习已经成为明确趋势**，科大讯飞、学而思等产品均已开始向学情分析、个性化学习与路径规划演进；但目前这些能力仍多以**功能化、局部化**形式存在，市场尚缺少一个长期维护**个人认知状态**、并持续驱动**诊断—修复—验证—行动**的统一系统。

    7.每周固定量用户访谈（定性），产出归因
    8.漏斗判据追踪：100→50（第二周仍活跃）→20（两周内完成≥3次闭环）→10（愿意付象征性费用）——每级掉的人都要有原因记录

## 股权架构设计

### 知序双公司架构总报告

> [!important] 
> 主公司＝资产与业务公司（产品/IP/算法/数据/融资/商业），管理服务公司＝人的公司（招聘/管理/薪酬/绩效/研发服务）。
> 激励只发生在管理服务公司层，不直接稀释主公司股权。
#### 一、结构总览

```
                    刘祥（创始人/实际控制人）
                    ┌─────────┴─────────┐
            知序主公司              管理服务有限公司
        （资产与业务公司）              （人的公司）
        刘祥 90%＋管理公司10%     刘祥64%＋其他20%＋激励池16%
```

**股权穿透**

| 主公司权益             | 最终享有人         | 比例        |
| ----------------- | ------------- | --------- |
| 刘祥直接持有            | 刘祥            | 90%       |
| 管理公司10% → 刘祥64%   | 刘祥（间接）        | 6.4%      |
| 管理公司10% → 其他股东20% | 其他股东＝法代本人（间接） | 2%        |
| 管理公司10% → 激励池16%  | 激励池（间接）       | 1.6%      |
| **刘祥合计**          |               | **96.4%** |

#### 二、两公司分工边界

|      | 主公司                                             | 管理服务有限公司                    |
| ---- | ----------------------------------------------- | --------------------------- |
| 持有   | 品牌、LogiTrace、TCN/LEKT算法、代码、数据资产、商标、专利软著、商业合同、收入 | 无核心资产                       |
| 职能   | 战略、融资、重大商业决策、对外合作                               | 招聘、签约、薪酬、绩效、项目管理、向主公司提供研发服务 |
| BP口径 | 投资主体，拥有全部核心资产                                   | 仅提供人员与研发管理服务                |


#### 三、架构闭环

**① 资金流**：客户/用户付费 → 主公司确认业务收入 → 主公司**根据真实发生的研发、技术、产品及管理服务，与管理服务公司签订服务协议并按独立交易原则结算** → 管理公司支付人员工资、社保、管理成本、项目成本及合理服务利润。
（红线：不是"随便转一笔钱"——关联劳务须具有受益性，定价结合服务内容、功能、成本、市场情况，由会计/税务师定价留档。）

**② IP流（四类合同闭环，以备尽调）**：

```
员工        → 劳动合同/实习协议＋知识产权/职务成果约定（保密协议） 
外部合作者   → 项目合作协议＋IP归属/许可条款                 ├→ 成果/IP全部归属
外包        → 委托开发协议＋源代码交付＋IP归属               ┤   知序主公司
管理服务公司 → 主公司与管理公司的研发/技术服务协议             ┘
```

**③ 人流**：所有成员由管理服务公司签约、管理、发薪，向主公司提供服务。

**④ 决策流**：见第五节《决策权限表》。

#### 四、核心规则

1. **长期股权/期权激励原则上仅设置于管理服务公司层，不直接稀释知序主公司股权；具体激励对象根据岗位重要性、贡献度和长期绑定程度确定**（未来招核心算法专家/CTO不受"管理层"字面限制）
2. **管理服务公司预留16%长期激励额度，用于核心人员长期激励；具体采用期权、限制性股权、虚拟权益或其他合法方式，由律师根据实际情况设计**（代持为候选工具之一，不提前锁死）
3. 管理公司法代＝其他20%股东＝同一人（核心管理人员，非挂名）
4. 服务费按独立交易原则定价并留档（见资金流）
5. 最多两家公司，不加第三家

**三个层级的关系（这张表的核心结构）**

- **节点是里程碑不是任务**：只写"到不了目标就完不成"的那几个；每天做什么进 [[#当月执行清单]]，不进这张表

**状态只用四种**：✅过 / ❌没过 / ⏭顺延（备注写顺延到哪月）/ 🔄进行中

**月末复盘3句话写完：**
- ✅的月份 → 写**实际数字**（比验收指标好还是差、差多少）
- ❌的月份 → 写**卡在哪、为什么**——这行是半年后最值钱的内容
- ⏭的月份 → 写**顺延的真实原因**（人不够？目标定错了？被别的事挤掉？）

**加新行（新月份）——两种都行，推荐复制**
- **往后加行**：光标放表格最后一行末尾按 `Enter`
- **复制上一行**（推荐）：整行复制粘贴，只改月份/目标/节点——验收指标的写法格式月月保持一致
- 新月份统一往**最后面**加（Obsidian 表格不自动排序，行停在你放的位置）

> [!warning] 一条纪律
> 一个月**只有一个大目标**。发现塞了两件事（"上线+拉新"），说明该拆成两个月，或其中一件其实不重要。这张表的价值就在于逼你每月只赌一件事。
