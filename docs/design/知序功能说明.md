# 知序功能说明

> 版本整理日期：2026-09-11  
> 对象：产品介绍、对内对齐、对外沟通  
> 口径：只写用户能感知的功能；标注「已有 / 排期」

---

## 1. 产品是什么

**知序**是面向个人学习者的 AI 知识工作台。

把教材放进自己的资料库，自动出题与刷题，需要时叫辅导；学习伙伴 **Tina** 根据你的**目标**和学情，安排**今天该做的几件事**。打开软件时，清楚自己要去哪、现在怎样、下一步做什么。

一句话：**先学得成，再讲得见。**

---

## 2. 谁在用 · 怎么进

| 项 | 说明 |
| --- | --- |
| 使用者 | 需要系统刷教材、备考或长期推进某一学习目标的个人用户 |
| 账号 | 支持注册 / 登录；每人一份自己的资料、题目与进度 |
| 入口 | Web 工作台（侧栏置顶：主页、驾驶室；工作台：Tina、笔记、资料；学习：进度、学习路径等） |
| 上手 | 新手引导：定称呼与角色 → 确认学习目标 → 可选上传第一份资料 |

---

## 3. 一条主使用路径

1. **定目标** — 用一句话写下长期要达到什么（例如「备战考研，主攻大学数学」）  
2. **放资料** — 上传教材到学习区，解析成分页内容，并抽出章节目录  
3. **按页出题** — 按章勾选页码，生成题目进入个人题库  
4. **刷题** — 对 / 错 / 不会；不会可看解析与原文，可进入辅导  
5. **看主页** — 系统给出当天 1～3 件可跳转的事；做完由程序判定，无需自己勾选  
6. **看驾驶室** — 掌握度、学情、目标进度与 Tina 判断收成一块总控（与主页同侧）  
7. **和 Tina 聊** — 检索自己的书、问概念、调整目标与安排；讲题时可用画布（排期）

## 4. 用户视角示例

下面用一个普通备考用户的一天，说明「打开知序之后实际会经历什么」。不写接口，只写人的感受。

### 角色

**小周**，研一备考中，目标是「研究生上岸，主攻高等数学」。上周刚注册知序，已经上传过一本《高等数学》讲义。

### 傍晚打开「主页」

小周登录后先看到主页：

- 上面仍是那句目标，距离他设的节点日期还有一百多天。  
- 中间有一块「我现在怎么样」：整体掌握大概六十多，最薄弱写着「极限与连续」。  
- Tina 用一两句话点出：计算题做得还行，卡在「极限在不在」这类判断上。  
- 下面今日三件事，都是可以点进去的：  
  1. 给「极限」相关几页再出一组题  
  2. 刷昨天不会的 8 道  
  3. （若资料不够）补传一章讲义  

他不用自己排日程，也不用勾选「我完成了」——做完对应动作，系统会自己判定。

### 按页出题

他点进第一件事，来到出题页：

- 左边按章列着目录，他勾选「极限」那几页；  
- 中间能预览该页正文；  
- 右边点批量出题，看着每一页进度往前走。  

题进了自己的题库，带着页码和知识点。过一会儿，主页上第一件事会变成已完成。

### 刷题，碰到「不会」

第二件事带他进刷题。一道存在性判断题他没把握，选了「不会」：

- 能看到解析，也能回到讲义原页；  
- 他点「辅导」，Tina 不急着给最终答案，而是追问他卡在哪；  
- （排期中的画布）讲夹逼或图像时，对话旁边还能出函数示意，不再只靠纯文字。  

刷够任务约定的道数后，第二件事同样自动完成，并弹出「该任务已经完成」。

### 再问 Tina 一句

睡前他打开 Tina：「明天还用盯极限吗？」

Tina 结合他的目标和今天作答，建议继续补「存在性」几页，或从薄弱点再练一组。他随手把一句关键提醒收成 tip，明天开刷前可以翻一下。

### 他感受到的闭环

| 他想做的事 | 知序怎么接住 |
| --- | --- |
| 我要去哪 | 目标一直在 |
| 我现在怎样 | 驾驶室里的学情与薄弱点说人话 |
| 今天干什么 | 主页上少量可跳转任务，做完自动算 |
| 书在哪、题从哪来 | 自己的资料 → 按页出题 → 题库 |
| 不会怎么办 | 解析、原文、辅导；（排期）画布讲得见 |
| 明天怎么办 | 再看主页 / 问 Tina |

一句话：小周不用管理复杂课表，只要反复走「看主页 → 学/练 → 不会再问；需要总览时进驾驶室」，知序把教材变成每天能推进的几步。

## 5. 功能详表

### 5.1 账号与上手

| 功能 | 状态 | 用户感知 |
| --- | --- | --- |
| 注册 / 登录 / 登出 | 已有 | 多用户隔离，资料与进度属于自己 |
| 个人资料 | 已有 | 昵称等基础信息 |
| 新手引导 | 已有 | 对话式走完目标与可选上传 |

### 5.2 主页与驾驶室

| 功能 | 状态 | 用户感知 |
| --- | --- | --- |
| **主页**（原「今天」） | 已有（改名中） | 问候、当前目标摘要、今日 1～3 件可跳转任务；日常行动入口 |
| 今日任务列表 | 已有 | 每天少量可点击完成的事（上传 / 出题 / 刷题等） |
| 任务自动完成 | 已有 | 上传成功、出题落库、刷够题数后判定完成并提示 |
| 当前目标展示 | 已有 | 看见长期那句话与有效期相关信息 |
| **驾驶室**（设计稿 `docs/dashboard_v3.html`） | **已有（边界见下）** | 与主页**同侧置顶**；掌握标尺、目标、薄弱行、Tina 判断、连击、建议行动（gaps + 日任务）；假周环比 / 假人格不做，详见 [驾驶室实现边界.md](./驾驶室实现边界.md) |
| Tina 建议 / 学情摘要 | 已有（持续增强） | 「我现在怎么样」「为什么是这样」类判断，主要落在驾驶室 |

> 说明：早期没有独立驾驶室时，总控内容挤在「今天」里；现拆开——**主页管今天做什么，驾驶室管我处在哪、系统为何这样排。**

### 5.3 目标

| 功能 | 状态 | 用户感知 |
| --- | --- | --- |
| 创建 / 查看 / 更新目标 | 已有 | 一人强调一条进行中的目标 |
| 目标详情与学习材料关联 | 已有（持续增强） | 从目标进入相关学习动作 |
| 按目标过滤学习路径 | 排期对齐 | 选目标后路径只谈相关范围，表述诚实 |

### 5.4 资料（知识库）

## 6. 排期中的重点（对外可讲）

### 6.1 驾驶室

**要解决的事：** 打开软件仍要在多个页面拼「我该干什么 / 我现在怎样」；早期又把总控内容硬塞进「今天」。

**做成什么样：** 侧栏与**主页同侧**单独开「驾驶室」（设计稿即 `dashboard_v3.html`）：掌握度、目标进度、学情、「Tina 为何这样判断」、近期活动一眼收齐。主页只保留问候与今日任务。

**落地进度：** 页面与真数据主路径已接；设计稿里「较上周 +x%」、战略型人格、Learning OS 式行动链等**暂不接假数**——清单见 [驾驶室实现边界.md](./驾驶室实现边界.md)。

### 6.2 讲题画布

**要解决的事：** 高数等科目纯文字讲不清图像与过程。

**做成什么样：** Tina / 辅导讲题时，右侧（或副屏）出现函数图、简单演示；对话里有入口，一点就看见。

**落地进度：** 首版已接——`show_plot` / `show_canvas` SSE、聊天旁副屏、气泡卡片；数据挂本用户会话 `payload`（隔离口径见 [讲题画布.md](./讲题画布.md)）。辅导页画布、更丰富示意后续再补。

### 6.3 TCN / 学科掌握（体验收口）

**已有：** 封闭学科、词表出题、作答回写、图谱资源等主线已差不多接上。

**还差：** 注册即可建档、Key 与失败不挡学习等体验缺口（产品日程继续补齐）。

## 7. 明确不做（当前产品边界）

- 不做把一天排满的传统日历日程  
- 不做用户手勾「我完成了」代替学习结果判定（今日任务以学习动作为准）  
- 不让模型随便编教材页码；出题与任务页码来自目录 / 解析  
- 前端不直连外部掌握度引擎；学科与回写由知序服务侧完成

## 10. 对外介绍可用的三句话

1. **知序**帮你把教材变成每天能推进的学习：出题、刷题、辅导，都在自己的书上。  
2. **Tina**根据目标和学情安排今天几件事；程序根据你是否真的学了来判定完成。  
3. 下一步把**驾驶室**从主页旁真正落地（总控看学情），并用**讲题画布**让高数等科目讲得见；TCN 主线已接通，继续补建档等体验。
