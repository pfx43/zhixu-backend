Flutter State

状态管理从简到繁：setState、InheritedWidget、Provider、Riverpod。选型先看「状态活在哪一层」，再决定要不要引入库。

什么时候用 setState

只影响当前 Widget、不会跨页面共享的局部交互，用 setState 就够。动画开关、输入框即时校验、折叠面板都属于这一类。不要为了「看起来专业」一上来就上 Riverpod。

InheritedWidget 在中间

它解决的是「向下传递、按需重建」。Provider 本质上是对它的封装。读资料时如果还分不清「谁在 listen、谁只是读一次」，先把这一层补上，后面的对比会顺很多。

刷题时容易错的点

  • 在 build 里发请求或改全局状态
  • 把本该局部的 UI 状态塞进全局 Provider
  • listen 范围过大，导致整棵子树无意义重建
下次开刷前先过一遍：状态该不该共享，以及 rebuild 的边界在哪。
