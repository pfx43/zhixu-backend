Widget 的 build 方法最恰当的描述是？

A.可以随意产生副作用，例如直接改全局变量
B.应尽量保持纯净，根据当前配置返回 UI 描述
C.只能返回 StatefulWidget
D.每次调用都必须配合 setState
回答错误，参考：B
build 描述「现在长什么样」，不应在其中做网络请求、写文件等副作用。状态变化应走 setState / 状态管理，再触发重建。
引用来源：Flutter 核心组件 · 第 3 章 Widget 生命周期

填空题 · Flutter 核心组件

若要在 Widget 树中向下共享数据、且不必层层传构造参数，常用的是 InheritedWidget。

回答正确
InheritedWidget（以及基于它的 Provider 等）沿树向下暴露数据，子节点通过 dependOnInheritedWidgetOfExactType 获取并订阅更新。
我选了 InheritedWidget，是对的。

简答题 · Flutter State 管理

为什么不建议在 build 里直接发起网络请求？请用一两句话说明。

build 可能被多次重建，把请求放进去会重复打接口，而且网络是副作用。
回答正确
AI 评语：答案点到了「反复重建」和「副作用」两处，表述完整。
build 可因父节点、主题、约束变化反复执行。把请求放进 initState、监听器或状态管理，才能避免重复请求和不可预期的 UI。
