## 功能更新

这份由**彭飞翔**整理（前端同学），写清「为什么要做、做成什么样」。认领和分支见 [next.md](./next.md) 与 [彭飞翔.md](./彭飞翔.md)。后端按 A→B→C→D 做；tip 接现有笔记接口。TCN 规则和认领见 [TCN集成.md](./TCN集成.md)。不要另做日程、日历、勾选完成。

### 一. 目标和任务系统

#### 为什么会有

日程太重，也不好设计。程序现在缺两样东西：Agent 凭什么判断今天该干什么；用户打开软件时，怎样才算「在用对的方式推进」。所以加目标和任务。目标是长期那一句；任务是当天几件清楚的事，不是把一天排满的日程。

#### 实现

**目标：** 用户想靠这个程序达到什么，例如「研究生上岸」。字段：描述（那句话）、属性（科目 / 对着哪类资料等）、有效期。一人同时只强调一条进行中的目标。到期或结业靠测量（题、tag），不是用户说「我学会了」。

**任务：** 每天 1～3 件可跳转的事，用来推进目标。例如看某章、出某几页的题、刷指定题号。Tina / 任务 Agent 派，**程序判定完成，用户不能勾选**。完成时弹窗固定：「该任务已经完成！」 任务写进同一张 `daily_tasks`，不要每人一套表、也不要对话里另写一套。

派的顺序：没书 → 上传；有书没题 → 按章出题；有题 → 按章或按缺口刷。前置：[目录和段页码](#二-书本目录提取段上带页码) 和 [Agent 升级](#三-agent升级)。

这一期三类任务，**都能自动确认**：不是用户勾选，是检查器挂在已有成功路径后面，看见学习动作的结果。

1. **上传资料**  
   资料不够时派。点去完成：进资料页上传，或在 Tina 对话里弹出上传窗口。两条路都走现有上传接口，不是新通道。  
   为什么能自动完成：文件一旦进库，这个用户的学习区就多了一本书。检查器看见「多了能解析的文档」就标完成，和交卷、按页出题看见结果是同一类事。聊该传什么是对话的事；传没传成功是检查器的事。不要另做「我传完了」接口。  
   传的不是任务里说的那本：这一期仍然算完成。检查器不读文件名、不对内容做语义匹配（会猜错，也会把人卡住）。对不上目标是缺口，不是「没完成」。下一次 `ensure` / Tina 再看目标和书单，缺的还在就再派上传或让 Tina 在对话里说明还缺什么。空文件、解析失败、按 hash 去重没有新书：不算多了文档，任务继续挂着。

2. **按页出题**  
   有书没题、或某章还没题时派。payload 里是书 id + 页码（页码来自目录，禁止模型手填）。  
   点去完成：进**出题页**（设计稿 `generate.html`， 同一套三栏：左按章勾页、中预览原文、右「AI 批量出题」+ 每页进度）。任务跳转要带上书和预勾选页（设计稿 `?from=tina`），人可以改勾选。Tina 对话里出题也行，不要在聊天里另开一个出题 Agent。  
   两条路都走按页出题。出题页不要只打一次 `generate-from-pages` 干等，或后台跑、但必须把页每页进度推给出题页。不要把内部交题工具挂到对话 Tina。  
   页列表要能显示「已出题 N」（知序现在没有，因为题目没存页码）。勾选上限跟 `max_pages_per_gen` 走，设计稿是 10。  
   为什么能自动完成：那些页上已经有题。检查器查 payload 页的题数，不要看 HTTP 刚返回的 `processing`，也不等整本 `question_gen_status=completed`。  
   人改勾选、只出了别的页：payload 仍空着，任务继续挂着。多出了别的页、但 payload 里的页已经有题，算完成。检查器不对「是不是这一章」做语义判断。

3. **刷题**  
   上线时看目标和题库，从某章或「没做 / 错 / 不会」里抽出题号写入任务。点去完成：刷题页用这些题目 id 开会话。**完成条件：** 任务范围内交够约定道数。交了就算（含「不会」），不要要求全对，否则点「我不会」会把任务卡死。

不要做勾选完成的 API。上传 / 出题 / 交卷成功后，检查器返回 `completed_tasks`，空就不弹窗。

### 二. 书本目录提取、段上带页码

#### 为什么会有

出题已经能按页，刷题却还像随机抽。用户没法按章刷、按章复习。任务要「出某章的页」「刷某章」，也必须有目录。

另外：Tina 检索命中的是**段落**，出题接口要的是**页码**。段上没有页码，检索到了也无法出题，只能猜页——不许猜。所以**抽出目录**和**段上带页码**是两件事，都要做。不是向量化。

#### 实现

上传、解析、切段照旧。之后多两步（后台即可）：

1. **抽出目录（章 → 页）存进这本书**，前端出题页按章分组勾选（设计稿左侧已经是这样）。优先用书里已有的目录 / 标题 / 书签对页码。不要只把前几页丢给 Agent（知拾 learning_path 读前 8 页，且**没有页范围**，出题页只能扁平「第 N 页」）。Agent 只能作补充，不能现场编页码。
2. **切段时给每段写下 `page_start` / `page_end`**（一段可以跨页）。关键词检索命中原样带上书 id 和这些页。旧书要补一次，不能只对新上传生效。

按章出题、按章刷、检索后再出题：都是程序拿目录或命中上的页码，调用现有按页出题。不要把搜到的那段话丢给另一个 Agent 再猜页。

### 三. Agent 升级

#### 为什么会有

现在对话里的 Tina 几乎只会检索；知序出题 Agent 还不能看邻页（知拾已经能）；没有专门布置任务的 Agent。目标和按章学习接不上。

下面「Tina 框架」= 我们用的 Agent 库；「对话 Tina」= 用户聊天那个。新工具都用框架来挂。任务 Agent 的「布置」必须写入第一节那张 `daily_tasks`，不要另写一套。

功能 D 表里是最小必做（读目标、看目录、按页出题、看缺口、写入今日任务）。下面是对话里还要挂哪些、怎么展示，两边同一套积木，不要做两套任务。

#### 实现

身份只来自登录。工具参数里不要 `user_id`。文档 id / 题目 id 都要再验是不是这个用户的。

##### 1. 对话 Tina

提示词里带上：这个用户有哪些资料（没有就写无）、当前目标、任务 Agent 已经布置的今日任务。

工具：

- **检索知识库：** 可选资料 id（没有就在自己的库里搜），加关键字、top_k。返回片段必须带书名、文档 id、页码（来自第二节入库字段，不是模型填的）。没有页码就等于工具废了。
- **资料详情：** 用资料 id 取名称、按目录的题目数、知识点 tag 及数量。
- **按目录取题：** 书 id、目录名、类型（做过 / 错 / 不会 / 没做）→ 题目 id 列表。
- **按知识点 tag 取题：** 书 id、题的知识点 tag、类型 → 题目 id 列表。
- **展示题目：** 聊天里嵌一块可作答的题（SSE 块 / 前端组件），参数是题目 id。不是新出题通道，也不要整页跳走才算展示。
- **上传资料：** 对话里弹出上传窗口，走现有上传；成功与否由检查器看学习区是否多了书。
- **读 / 改目标、布置今日任务：** 走功能 D 那几个入口，写入同一张表。

不要把出题内部的 `submit_question` 挂到对话 Tina 上。

##### 2. 任务 Agent

提示词里带上：资料列表、各书章节和题量、最近任务完成情况、当前目标和有效期。

工具：按目录取题、按知识点 tag 取题（同上）、**任务布置**（写入 `daily_tasks`。kind / 完成规则由程序定，Tina 只写标题和理由）。

##### 3. 出题 Agent（内部，不是对话 Tina）

工作单位是**页**：出题页或 Tina 工具交出 `document_id` + 页码，服务按页取出正文，**每一页新建一个 Agent**（用完即丢），不跟用户聊天。页码由服务传入，Agent 不能自己改出哪些页。

知序现在只有一个 `submit_question`，正文截断后看不见上一页。

不要把这个 Agent 挂进主对话。

##### 4. 辅导 Agent

仍跟刷题会话走。进入新题时，提示词换成这题的题干、答案、解析。工具这一期先不扩。

### 四. 特色功能 tip

#### 为什么会有

笔记是用户自己沉淀下来的长内容（自己写、AI 摘要、学习报告）。

tip 不是第二种笔记首页。它是用软件时随手留下的短卡片：解析里一句、Tina 说的一句、资料里划到的一句，觉得以后开刷前能翻一翻，就收进来。给「过最近几张」，不是档案柜。

所以笔记页做成两个 tab：笔记 | tip。不要混成一个列表。

#### 长什么样（设计稿已经能点）

1. **划选触发**  
   在 Tina 对话、刷题辅导里，划一段字（大约 4 个字以上）。选区旁边冒出一个绿色小按钮，写着 **tip**。点侧栏、输入框里的字不会出这个按钮。

2. **收入弹层**  
   点 tip 打开「收入 tip」：上面是划选原文（引用块），下面填标题（可改，默认截一句）、关联哪本资料（可以不关联）、**tag**（用户自己给这张 tip 分类）。取消或点遮罩关掉。点「收入 tip」后进笔记页的 tip 堆，新的在最上面。

   tag 不是书或题目上的知识点。那是用户觉得这张卡片属于哪一类，例如「英语难词」「易错公式」「下次开刷前要看」。同一句原文，不同人可以打不同的 tip 类型。设计稿里还有一排「主题」chip，和 tag 重复的话只保留用户自己的类型，不要和资料 / 出题的知识点 tag 混用一张表。

3. **笔记页的 tip 堆**  
   默认几张牌叠在一起，左边一条鼠尾草绿。点最上面一张会抽到最底下（下一张也行）。「全部展开」铺开；再点其中一张会重新叠回去。每张牌：角标 tip、标题、引用原文、关联的书、从哪划的（Tina 对话 / 刷题辅导 / 资料阅读）。点开是详情，可以补一句「为什么留下它」。返回走 tip 堆，不是笔记列表。

4. **对话里也能看见、也能让 Tina 做**  
   用户说「把跟 build 有关的 tip 给我看」，Tina 在聊天里摊出相关的几张小卡片，整摞仍在笔记页。用户说「把刚才那句做成 tip」，Tina 做好后聊天里出现一张新 tip，链到 tip 堆。AI 侧仍然平铺正文，不要头像。

右侧今日状态里可以出现「新 tip」条数，不是独立功能入口。

#### 实现（给后端同学）

划选和堆叠 UI 在前端。后端不要为 tip 另做一套表。

- 落库走现有笔记接口，`note_type` 用 tip（和 `manual` / `report` 分开）。标题、正文（划选原文）、关联资料（`collection_id` 或文档 id，可空）用笔记已有字段。来源（Tina / 刷题 / 资料）写进正文或扩展字段，列表要能筛出来。
- **tip 的 tag**：存的是用户给这张短卡片打的类型（难词、易错点……），按当前用户隔离。列出、筛选、Tina「把某类 tip 拿出来」都走这套 tag，不要拿题目 / 文档的知识点 tag 来冒充。用户没打 tag 也可以收。
- 创建必须带当前登录用户。列表：`note_type=tip`，新的在前。删号时跟笔记一起删。
- Tina 读 tip、代做 tip：只动这个用户的 tip。代做时标题和关联资料由程序填，不要让模型编文档 id；tag 能从用户这句话里带上的才写，不要替用户乱分类。
- 设计稿现在写在浏览器 `sessionStorage`，接真接口后换掉。这一期不要做成任务，也不要日历。

站在积木「笔记」上。堆叠怎么翻是前端的事；后端负责存、按用户隔离、能按 type 列出。

### 五. TCN 知识点（书学科 + 词表出题 + 交卷追踪）

#### 为什么会有

以前题目知识点 tag 是出题模型自己编的。接 TCN 之后改用引擎图谱上的节点（人工维护），交卷才能告诉引擎「这个人在哪个节点对了或错了」。不接的话 Tina 看缺口、结业测量都对不上一张稳定词表。

#### 实现

知识点 tag **只来自** [tcn-knowledge-tags.md](../api/TCN/tcn-knowledge-tags.md) 里的 `name`。`id`（如 `higher_math:夹逼准则`）只在交卷时查表，不要让前端或模型填写节点 id。

上传并抽出目录时，Agent 只从封闭学科名单里判这本书属不属于（现在只有 `higher_math`），不属于或拿不准就 `None`。不要猜，不要自造学科名。页码仍禁止编。

书属于某学科时，出题 prompt 带上该学科的 tag 名单；输出不在名单里的题打回。书是 `None`：出题刷题照旧，不调 TCN。

`predict` 挂在刷题提交：对 → `correct`，错 → `incorrect`，点「不会」不传。失败不影响交卷成功。不要接 TCN 的 goals/today。tip tag、用户画像 tag 不是知识点。

书信息上能看到学科，以后允许人改（只影响新出的题）。刷题请求不要带 `tc_node_id`。

认领、跟 TCN 要的服务 Key / 建档、别做： [TCN集成.md](./TCN集成.md)。

## bug 修复

不是新功能。修的时候不要顺手改产品口径。

1. **TCN 链接**  
   配 `TCN_BASE_URL`（或等价配置），不要把整站请求打到错误地址、更不要因此把站点打挂。链接失败要降级，不要拖死主流程，这个和会议说的一样，在王晨调查完之后再修改

2. **关键词检索漏检**  
   现在 `LIMIT 200` 且没有按相关度排序时，命中可能排在后面被丢掉。检索结果要能按匹配排序再截断；返回时带上段上的页码（见功能 B），没有页码不要让工具去猜。

3. **SSE 字段不要一锅端**  
   按 `type` 组字段。不要给所有事件都塞空的 `content`。展示题目、上传窗口这类块走自己的 type，前端才知道是嵌组件还是纯文本。

4. **聊天热路径**  
   主对话已经走 `llm_pool`。不要把默认路径退回 `TinaGateway` 的 key lease 旧写法。
